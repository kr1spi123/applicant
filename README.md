# Проект «Приемная комиссия» (Applicant)

Проект на Laravel для автоматизации работы приемной комиссии.

## Синхронизация между несколькими компьютерами

Если вы работаете над проектом на двух разных ПК, следуйте этой инструкции, чтобы поддерживать код и базу данных в актуальном состоянии.

### 1. Перенос кода (GitHub)
Код синхронизируется через Git. Перед уходом с одного ПК сделайте:
```bash
git add .
git commit -m "Описание изменений"
git push
```
На втором ПК перед началом работы:
```bash
git pull
```

### 2. Синхронизация базы данных (Migrations & Seeders)
В Laravel **не нужно** постоянно экспортировать и импортировать `.sql` файлы. Структура и данные синхронизируются через миграции и сидеры, которые уже есть в коде:

*   **Если вы изменили структуру** (добавили поля, таблицы):
    На втором ПК после `git pull` выполните:
    ```bash
    php artisan migrate
    ```
*   **Если вы хотите обновить тестовые данные** (специальности, заявки):
    Выполните:
    ```bash
    php artisan db:seed
    ```
    *Совет: Команда `php artisan migrate:fresh --seed` полностью пересоздаст базу и заполнит её свежими данными из сидеров.*

### 3. Файл настроек (.env)
Файл `.env` **не передается** через GitHub (он в `.gitignore`). Вам нужно один раз настроить его на каждом ПК:
1. Скопируйте `.env.example` в `.env`.
2. Укажите данные для подключения к вашей локальной БД (`DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`).

### 4. Изображения
Фотографии специальностей теперь сохраняются в `public/assets/img/specialties`. Эти файлы **отслеживаются Git**, поэтому при `git push` и `git pull` они будут автоматически переноситься между вашими компьютерами.

---

## Основные команды
*   `php artisan serve` — запуск локального сервера.
*   `php artisan migrate` — применение новых миграций.
*   `php artisan db:seed` — заполнение базы тестовыми данными.
*   `npm run dev` — запуск сборки фронтенда (Vite).
